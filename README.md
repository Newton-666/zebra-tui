# Krystal

多 agent 团队驾驶舱 —— 一个终端窗口，指挥整支 agent 团队。

前端基于一个 vendored 的开源 TUI 框架（`deps/`，MIT）：差分渲染、无闪烁、圆角框编辑器
（「两条线中间的输入框」）、@ 自动补全、ScrollView、Stack 布局。
应用层（团队网格、tmux 引擎、团队历史、拖拽调宽、协作层、logo）是 Krystal 自己的。

## 架构

```
┌─ Krystal TUI ────────────────────────────┐
│ logo 框 / 团队网格（可拖拽分隔线）/ 状态行 / 输入框 │
└──────────┬───────────────────┬───────────┘
           │ tmux send-keys    │ tmux capture-pane（350ms 轮询）
           ▼                   ▲
    tmux 会话 zebra-<id>（引擎室：每个成员一个真实交互窗格）
```

- 成员以**真实交互 CLI** 生活在 tmux 引擎室里（会话、审批、界面全保留）
- Krystal 是视图 + 遥控器：轮询显示各成员实时画面，输入框分发指令
- 拖拽中间的分隔线可调列宽：**引擎窗格同步缩放**，成员按新宽度重排，排版不破坏
- `tmux attach -t zebra-<id>` 随时直看任意成员的原始窗格

- **新建团队**：手动配 1–6 名成员（名字 / 类型 / **模型** / 启动命令），并给每名成员写一句身份
- **一句话建队**：写一句目标（如「Rust CLI 小工具，一人实现一人测试验收」），
  由内置的一次性生成器（按可用性与延迟自动选择）整理成
  **队名 + 目标 + 成员职责 + 协作协议**，确认后一键建队
- **历史群聊**：恢复历史团队（回放团队视图 + 重接 tmux 引擎）

## 运行

```bash
git clone https://github.com/Newton-666/zebra-tui && cd zebra-tui
sh scripts/vendor-tui.sh        # 把 TUI 框架 vendor 到 deps/（仓库不提交第三方代码）
./zebra                          # 首次：Krystal 初始界面
```

可选：装成全局命令

```bash
ln -sf "$PWD/zebra" ~/.local/bin/krystal
```

要求：`tmux`、Node ≥ 22.6（跑 TypeScript 用 `--experimental-strip-types`）。

团队数据都在 `sessions/`；测试可用 `KRISTAL_SESSIONS_DIR` 指到别处（冒烟测试默认已隔离）。

## 用法

命令前缀 `:` 与 `/` 等价（`:model` = `/model`）；**未知命令只会提示，不会广播给成员**，
避免把别家的斜杠命令误发进成员会话。

| 输入 | 效果 |
|---|---|
| `消息` | 广播全体（或 `:to` 锁定的目标） |
| 行首 `@` | 弹出成员补全（↑↓ + enter） |
| `@alpha @beta 消息` | 定向多个成员 |
| `:to <name>` | 锁定默认目标（`◈` 标记，`:to all` 解除） |
| `:model` | 打开模型选择弹窗（成员 → 来源 → 模型）；`:model <成员>` 直达该成员的来源 |
| `:model <name> <模型>` | 运行时切换该成员模型：用新命令重启它的窗格并重新注入身份 |
| `:role <name> <一句话>` | 设定/修改该成员身份：首次注入完整身份，之后只发精简「身份更新」（不在成员上下文里留两份职责） |
| `:brief` | 重发身份与团队简报（`:brief <name>` 只发给某成员） |
| `:team` | tmux 引擎丢失时重建 |
| `:help` | 命令与快捷键帮助（浮层） |
| `:quit` / `ctrl+c` | 退出（tmux 引擎保留在后台） |
| 滚轮悬停某格 | 单独滚动**该成员**的画面历史（每格独立累积快照；向上滚看历史，向下滚回到最新） |
| 拖拽分隔线 | 调整列宽（同时缩放引擎窗格） |

## 模型选择

**建队时选**：向导里选完类型后进入模型选择，来源与清单**读取各个 agent 自己的配置/缓存**
（不写死、不猜测），分成「来源 → 具体模型」两级，另有「默认（不指定）」与「自定义…」：

| 类型 | 模型来源 |
|---|---|
| 预设 A | 该 agent 的模型目录文件（providers → models，含上下文长度提示） |
| 预设 B | 其 provider 模型缓存 + 当前默认（来自它的 config） |
| 预设 C | 其模型目录文件 |
| 预设 D | 其 config.toml 里的模型别名 |

模型来源会按该 agent 的**当前 provider** 优先排序，其他来源标注「需该 provider 已配置密钥/端点」，
避免选到它跑不起来的模型。

选定后写进 `team.json` 的 `members[].model`，并**拼接进启动与恢复命令**：

```
pi      --model bigmodel/glm-5.3-flash        （恢复：… -c || …）
hermes  -m glm-5.2 chat                       （恢复：… chat --continue || …）
kimi    -m <alias> -c || kimi -m <alias>
codex   -m <slug> resume --last || codex -m <slug>
```

**运行时切换**：`:model <成员> <模型>` 会用新模型重启该成员的窗格（保留会话历史，走恢复命令），
并把它的身份重新注入（重启后上下文是新的）。

## 一句话建队与「预置协议」

`team.json` 里三个字段都会进入成员的上下文与白板：

| 字段 | 作用 |
|---|---|
| `goal` | 团队目标，写进身份/简报与白板，成员一启动就知道要做什么 |
| `members[].role` | 每名成员的身份/职责（手动逐个输入，或由一句话建队生成） |
| `protocol` | 协作协议（谁起草 / 谁验收 / 产出格式 / 禁止事项），**预置到白板** |

**为什么协议要预置？** 不预置时，成员启动后会花时间互相谈判协议——反复互发「同意分工」
「确认」「再补一条纪律」，内容高度重复。预置之后，同一场景只剩一条简短握手：
实测互发从 7 条降到 1 条、白板冗余写入从 6 次降到 0 次。一句话建队让你用一行描述
就获得这份协议，既省 token 也免去来回对齐。

## 团队感知与通信

成员之间**互相知道彼此存在，并能直接通信**——不需要人类中转。

**① 身份注入**：每个成员窗格启动时带上身份环境变量：

```
ZEBRA_SESSION=<会话 id>   ZEBRA_MEMBER=<成员名>   ZEBRA_HOME=<会话目录>
PATH=<会话目录>/bin:$PATH        # 会话工具 `krystal` 可用
```

**② 身份（每次进群注入）**：每个成员有一句话身份/职责，持久化在 `team.json`。
注入策略：

| 场景 | 是否注入身份 | 原因 |
|---|---|---|
| 新建团队 | 是（全员） | 上下文是新的 |
| 引擎被重建后 resume | 是（全员） | 成员进程换了，上下文丢失 |
| 某个窗格崩溃被自动复活 | 是（该成员） | 新进程没有上下文 |
| resume 且窗格还活着 | 否 | 上下文里已有身份，重复注入会白烧一轮 token |

需要强制重发用 `:brief`。

**③ 团队简报（只发一次）**：更完整的那份（队友名册、协作命令、纪律）只在成员首次进群时注入，
全文写在 `sessions/<id>/BRIEF.md`。身份短、每次注入；简报长、只发一次——开局成本很低。

**④ 会话内协作命令** `krystal`（每个成员在自己终端里执行）：

| 命令 | 作用 |
|---|---|
| `krystal whoami` | 确认自己的身份 |
| `krystal roster` | 查看队友与在线状态 |
| `krystal send <队友> <消息>` | 给队友发消息（出现在对方会话里，前缀 `[from 你]`） |
| `krystal board [内容]` | 查看 / 追加团队白板（异步协作，落在 `board.md`） |

**⑤ 中继可视化**：成员互发的消息会实时显示在 Krystal 状态条（`alpha → beta: …`），
并作为 `relay` 事件写进团队历史。

**防循环**：同一对队友 60 秒内互发超过 3 条（或全局 6 条）会被自动拒绝，
并提示把结论写白板——避免陷入「互相确认」的死循环。

## 团队历史

每个团队一个目录：`sessions/<id>/`

- `team.json` — 成员、类型、启动/恢复命令、身份、目标、协议、列宽比例、窗格映射
- `BRIEF.md` — 团队简报（目标 / 名册与职责 / 预置协议 / 协作命令）
- `board.md` — 团队白板（创建时预置目标与协议，成员追加状态与结论）
- `history.jsonl` — 团队事件流：`team_created` / `dispatch` / `screen` / `relay` / `note`
- `bin/krystal` — 会话内协作命令

```bash
./zebra -c          # 恢复最近团队：回放团队视图 + 重接引擎（缺格会自动重建）
./zebra -r <id前缀> # 指定团队
./zebra --dir <p>   # 新团队的工作目录
```

## 成员类型

成员可以是**任意交互式 CLI**：向导内置几种常见 agent CLI 的预设（启动命令与恢复命令），
也可以选 `custom` 直接填自己的启动命令。每条成员记录包含：

```
name / type / command（启动）/ resumeCommand（恢复）/ color / role（身份）
```

恢复策略：`resumeCommand || command`，可用 `||` 串退路（如「续接会话失败则开新会话」）。

## 开发

```bash
npm run smoke    # 引擎 + 存储冒烟测试（无需 TTY；用 /tmp 隔离会话目录，不碰真实团队数据）
node --experimental-strip-types src/main.ts
```

代码结构：

```
src/
├── main.ts          入口（-c / -r / --dir）
├── app.ts           TUI 装配：logo 框 / 团队网格 / 状态行 / 输入框 / 拖拽 / 注入调度
├── view/grid.ts     团队网格（精确列宽 + 可拖拽分隔线 + 布局链委托）
├── view/cell.ts     成员卡片（圆角边框 + 定宽截断 tail）
├── view/wizard.ts   初始界面（logo + 模式选择）+ 配置向导 + 一句话建队
├── agents.ts        tmux 引擎（建格 / 分发 / 捕获 / 复活 / 窗格同步 / 身份环境）
├── poll.ts          画面轮询 + 死格自动复活 + 中继回流
├── team.ts          团队历史存储
├── kit.ts           团队工具包（bin/krystal 协作命令 + 身份 + BRIEF.md 简报）
├── generator.ts     一句话建队：一次性 CLI → 结构化团队规格
├── models.ts        模型发现（读各 agent 自身配置）+ 模型参数注入命令
└── ui/              ansi / logo / @补全 provider
```
