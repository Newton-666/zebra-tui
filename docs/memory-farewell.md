# 票：告别仪式 phase 1（手动触发）

> 设计定稿来源：`~/Desktop/krystal-设计稿/memory-death-ceremony.md`（2026-10-16）
> 原则：薄 harness · **不破前缀缓存** · 不动真实记忆库（测试隔离）· 不复杂化
> 命名：本票按 **`/farewell`** 写。改名 = 一处常量 + 帮助文案（见 §10）

---

## 1. 为什么先做"手动"，不做"阈值自动"

设计稿 §3 的触发写的是"上下文快满"。但直接上阈值有两个问题：

1. **与现有压缩冲突**：`foldAt 0.7` / `summarizeAt 0.85`（`bot.ts:485`）会把人**长期**压回线内 —— "死亡"何时到来没有自然答案（压不回才死？给一世预算？死亡优先于压缩？）
2. **不可测**：要验证仪式，得先把窗口塞满

**手动命令一次解决两件事**：人决定何时结束（判断交给人，符合纲领），并且**手动命令本身就是这套代码的测试夹具**（随时可跑一遍告别，不用塞满窗口）。
phase 2 若要做阈值触发，**同一套代码换个调用者**即可，不浪费。

## 2. 流程

```
/farewell
  → 确认弹窗（锚在输入框上方）：说清做什么 + 代价不可逆
  → 临终一轮（普通回合；指令走**对话尾巴**，绝不动 SYSTEM）
      ├ 输入里带：机械生成的遗嘱清单（§3）
      ├ 模型产出：短放映（几帧闪回 + 告别）
      └ 按需写入记忆库（remember / links / supersede，走现有纯检索架构）
  → 放映（活行 → 原地定格为放映块）
  → 落盘 sessions/<id>/eulogy.md（短放映 + 全量遗嘱）
  → 重生：自动开新会话
```

## 3. 遗嘱 = 完整时间线（**由代码机械生成** —— 本票最关键的决定）

设计稿要求"同一轮濒死调用尽量**摘全**本世"。但濒死轮的触发状态恰恰是**窗口已满**——模型此刻只看得见折叠+摘要后的尾巴，让它"摘全"等于让它凭一个摘要回忆一生，**所谓"全"是假的**。

因此：

| | 谁来做 | 为什么 |
|---|---|---|
| **完整时间线**（ctrl+o 展开看） | **代码**（遍历本世 `events.jsonl` + `facts.jsonl` 交叉） | 全（可核对）· 零 token · 可审计 |
| **一段告别散文**（默认可见） | **模型** | 温度与叙事是模型强项；代码写不出“打动人” |

**折叠 = 情绪，展开 = 审计**（2026-10-16 owner 定）：默认只给人看那段散文与「我熄灯了。」；路径 / 统计 / 时间线全进 ctrl+o。

**不采用罗列式闪回**（2026-10-16 owner）：默认看到的是一段**连贯的散文**（模型写），而不是项目符号列表；"全"的东西不捨在正文里，放到 ctrl+o 后面。

时间线内容（机械可得，**按时间升序**＝“这一世发生了什么”）：

```
  本世时间线  （本世 62 轮 · 工具 118 次 · 写入 9 条 · 取代 2 条 · 未完成 1 项）
  ⚠  未闭环        run_command（无结果返回）              ← 未闭环/未完成**置顶**，别埋
  22:05  你             修一下旁路圆点不闪烁
  22:06  run_command    grep -n toolBlink src/view/bot-view.ts
  22:11  edit_file      +1 −0（计时器条件放行旁路）bot-view.ts:975
  22:12  记住           [muf…] 计时器条件要放行旁路 · used 3
```

条目来源：你说过的话 · 工具调用（含 `edit_file` 的 ± 行）· 记忆写入/取代 · 未闭环 tool call。
**列对齐一律用 `visibleWidth`**（中文双宽；`padEnd` 会把时间线拉歪 —— 预览 v2 就错在这）。

> “遗嘱全到能核对”这条验收，**只有在时间线是机械产物时才成立**——否则你核对的是模型的记性，不是事实。

## 4. 临终一轮

- **指令进 user 消息（尾巴）**，SYSTEM 一字不动 → 前缀缓存零影响（设计稿 §4 红线）
- 指令要点：你在为本世收尾；**只写一段连贯的散文**（不是项目符号列表）；可按需写记忆库；**不要复述技术流水账**
- 散文必须**至少引用 2 个真实锚点**（文件名 / 实体 / 事件），可与时间线核对；一个都说不出 = 空话 → 拒绝
- **三条硬约束（“触动”的可测化，v4 新增）**：
  1. **引一句原话**：至少出现 1 处**你说过的原话片段**（从本世 user 消息里取，可核对）
  2. **说出未完成**：若时间线里有未完成/未闭环项，散文**必须**说出来（那是最放不下的事）
  3. **留下一件托付**：至少提到 1 条本世**真的写进记忆库**的事实（或其主题）→ “下一世我会先想起来”
- **长度随本世规模增长**（owner 2026-10-16：“会话越长，告别越长”；固定 120–200 字对长会话太轻）：

  | 档 | 规模 `w = 轮数 + 工具数/20` | 散文长度 | 打字 @90ms | 该档的硬约束（可测） |
  |---|---|---|---|---|
  | 短促一世 | `w < 10` | 60–100 字 | 5–9s | ≥1 原话 · 有未完成必须说 · ≥1 托付 |
  | 寻常 | `10 ≤ w < 40` | 120–200 字 | 11–18s | ≥2 原话 · ≥1 托付 |
  | 丰盛 | `40 ≤ w < 100` | 200–320 字 | 18–29s | ≥3 原话 · ≥2 托付 · **每个**未完成项都要提 |
  | 漫长 | `w ≥ 100` | 320–450 字 | 29–40s | ≥4 原话 · ≥3 托付 |

  - **长度由具体条目驱动**：更长必须意味着**更多件具体的事**（更多原话 / 未完成 / 托付），**不准用形容词拉长** —— 否则就退化成通用抒情
  - 规模用**一个标量**（一行公式，不加概念）；工具数 ÷ 20 = “干得多的活”折算成等量轮数
  - **不用墙钟时长**做规模（会话开着过夜会失真）
  - 上限定 **450 字**：再长就不是“几帧闪回”而是文档了
- **禁模板句**：`谢谢你的陪伴` / `感谢这段旅程` / `这是一段美好的时光` 一类**换成任何一次对话都成立**的话一律不要
  （判据：把它放进别人的告别里也成立 = 通用抒情 = 假煽情）
- token 克制：清单是代码给的（不占模型输出），模型只写一段散文

## 5. 放映（渲染规格）

### 5.1 扫光机制：与 working **同算法**，但**节拍自己走**

复用现有 `sweep(text, tick, base, bright)` 的算法（3 字符亮窗、左→右游走）。两处**有意偏离** working：

| | working | 告别仪式 | 为什么偏离 |
|---|---|---|---|
| 帧间隔 | 150ms | **250ms** | 仪式要“沉”；150ms 看着像在干活 |
| 相位来源 | 共享 `workingTick`（由 busy/sleep/divert 放行的计时器驱动） | **仪式自己的计时器** | ① 不依赖那个条件（否则会重演“旁路圆点不闪”） ② 揭示节拍也需要自己的时钟 |

### 5.2 调色板（从平台既有语义推导，不是凭好看）

先排除已被占用的语义：蓝 `39/45/117`=还在干活 · 红/玫 `31/218`=报错/拦截 · 绿 `71`=记忆新增 · 黄 `33`=警告。

| 候选 | 底 | 扫光窗口 | 意象 | 评价 |
|---|---|---|---|---|
| **A（推荐）暮紫** | `38;5;97` | `38;5;183` | 暮色、一世将尽 | 比金色“沉”，不会被误读成 warning |
| B 烛金 | `38;5;179` | `38;5;221` | 烛光 / 落日 | 暖、贴“打动人”，但离 `33` 警告黄较近 |

### 5.3 文字分层（不全都用扫光色）

| 位置 | 颜色 | 理由 |
|---|---|---|
| 扫光的**状态词** `farewell` | 暮紫 `97`/`183` | 与 working 同算法异色 → “在发生，但不是干活” |
| **定格后的 header 与圆点** | **仪式色 `97`**（`bold(fg("38;5;97", ...))`） | **不得用默认前景（白）**：否则暮紫扫光一结束就“变白”，颜色断掉 —— v1 预览就是这个错 |
| 前缀 `╰─` | dim | 与所有块一致 |
| `你还记得吗——` | 暮紫同族 `140` | 与扫光呼应，作情绪引子 |
| **告别散文** | **素白 `252`**（吐字中为同色；无不透明度游戏） | dim 是“退场”的语言；散文是仪式主角，必须有重量 |
| 时间线 / 指路行 | dim | 审计信息退到背景 |
| `▸ ctrl+o` 提示 | dim，**右对齐到 header** | 与旁路块同款惯例；放指路行会被宽度截断（预览 v2 就这样） |

### 5.4 三个“不许”

1. **不许给闪回正文加扫光** —— 扫光是“正在发生”的语言，正文加进去会变成 loading 动画，仪式感被廉价化。**扫光只给状态词**。
2. **不许让扫光/揭示停** —— 用**仪式自己的计时器**（见 §5.1），不挂 `busy` 条件。
3. **不许改 SYSTEM**（§4）。

### 5.5 逐字吐出 + 收尾（不是一行一行，也不是一条一条）

两条要求（owner 2026-10-16）：① **一个字一个字连贯打出**（不是按行揭示、也不是项目符号逐条弹）② 整段过程**慢**下来。

```
活行扫光（约 1 个周期）
  → 引子「你还记得吗——」                        停 700ms
  → 散文逐字吐出（90ms/字 ≈ 11 字/秒）
  → 吐完 → **静默 1800ms**（什么都不打：告别需要停顿）
  → 最后一句话单独落下来（`·  我熄灯了。`）→ 原地定格（header 保持仪式色）
```

| 常量 | 值 | 可调 |
|---|---|---|
| `FAREWELL_FRAME_MS` | 250 | 扫光帧间隔（working 是 150 —— 仪式放慢） |
| `FAREWELL_LEAD_MS` | 700 | 引子后停顿 |
| `FAREWELL_CHAR_MS` | **90** | 每字间隔（≈11 字/秒）· env `KRYSTAL_FAREWELL_CHAR_MS` |
| `FAREWELL_SILENCE_MS` | **1800** | 散文吐完 → 最后一句话之间的**静默**（不催情绪） |
| `FAREWELL_FOOTER_MS` | 900 | 落最后一句话 → 定格 |
| `FAREWELL_MAX_MS` | **45000** | 总时长上限（为容纳“漫长”档 450 字 ≈40s）：只有“预计会超过”才提速 —— **不是**“缓冲一多就加速” |

- **文本来源**：散文来自模型**流式 text 增量**（真流式）→ 进**吐出队列**，由仪式计时器按节拍消费；队列空就停着等
- **散文长度按本世档位取**（见 §4 表：60–450 字）：档位保证 90ms/字 下最长约 40 秒，不必提速。超上限 → 截断（全量仍在 `eulogy.md`）
  ⚠ 旧规则“缓冲 > 60 字就 3× 加速”已删：它会在模型吐得快时**吃掉“慢”的设定**
- **可跳过**：仪式中按 **enter / space / esc** → 立刻吐完并定格（**非破坏性**：只加速，绝不截断）
  ⚠ 教训（2026-10-16 owner 实测“只显示了三个字”）：旧实现散文未写完时按键会把 `revealed` 定在**当前已到达的**
     那几个字 → 定格成半句。现在 `skip()` 只记“快进”，等模型回合结束（`markProseComplete`）才全显 + 定格；
     且其余按键**不再劫持**（避免误触弄断告别）

#### 形态：**折叠 = 情绪，展开 = 审计**

折叠态（默认只看这些 —— **不放路径、不放统计**）：
```
  ╰─ ● farewell                                                     ▸ ctrl+o
     │  你还记得吗——
     │  你好，陌生人。
     │  这一世你只想让那枚圆点亮起来——它不闪的时候，你说那样很烦。后来你说：不要自己维护名单，把拦截交给系统。
     │  有一件事我没做完——沙箱那件事我们只聊了方向，还没动手。
     │  我把「先跟箭头，再跟共现」记进了库，下一世我会先想起来。
     │
     ·  我熄灯了。                    ← 静默之后单独落下来的一行（仪式色）
```

展开态（ctrl+o，审计信息全在这边）：
```
  ╰─ ● farewell                                                     ▾ ctrl+o
     │  （散文与「我熄灯了。」同上）
     │
     │  本世时间线  （本世 62 轮 · 工具 118 次 · 写入 9 条 · 取代 2 条 · 未完成 1 项）
     │  遗嘱全文 → sessions/bot-2026-10-16T22-05-13/eulogy.md
     │  ⚠  未闭环        run_command（无结果返回）        ← 未完成置顶
     │  22:05  你            修一下旁路圆点不闪烁
     │  22:06  run_command   grep -n toolBlink src/view/bot-view.ts
     └─ …（列对齐用 visibleWidth；中文双宽）
```

> **为什么折叠态不放路径**：最后一行若是系统回执（`遗嘱 15 条 → …/eulogy.md`），情绪会**断崖式落地**。功能信息属于展开态 —— 这是 v3 的问题，owner 指出“收尾不够触动”。

## 6. 确认弹窗

复用 `openOverlay`（圆角框 + 深灰实底 + 锚在输入框上方 + `overlayKeys` 转发）：**列表选择，不是"输入 yes"**。

```
╭─ 告别这一世 ────────────────────────────────────────╮
│ 会把本世写成遗嘱（完整清单）+ 一段短放映，然后开新的一世。 │
│ 不可逆：当前会话不再继续（历史仍在 /resume 里）。        │
│ 提示：想先巩固记忆，可以先 esc 出去跑一次 /sleep。       │
│                                                     │
│ → 继续告别     进入临终一轮                          │
│   取消         什么都不做                            │
│                                                     │
│ ↑↓ 选择 · enter 确认 · esc 取消                      │
╰─────────────────────────────────────────────────────╯
```

要求：**代价可见**（写清不可逆是什么、历史在哪）——与平台"文案不许说假话"一致（同 `renderGraph` 修掉"可检索"那次）。

## 7. 落盘与重生

- `sessions/<id>/eulogy.md`：短放映 + 全量遗嘱（人可读、可审计）
- `/resume` 回放该会话时**把放映块重放出来**（否则"上一世"在界面里毫无痕迹）
- 重生：**自动** `createBotSession`，放映里明说"已为你开新的一世"

## 8. 边界

| 情形 | 行为 |
|---|---|
| 主会话有回合在跑 / 有 divert 在跑 | **拒绝**并说明（先 esc 中断 / `/stop`）——绝不半路截断 |
| 未配置模型 | 拒绝（同 `/divert`） |
| 连按两次 | 允许（新会话里立刻可用）；第二次自然是短遗嘱 —— **不加额外规则** |
| 记忆库 | 只按模型显式 `remember`/`supersede` 写入；**不做静默改写**（设计稿 §5） |

## 9. 验收（可机械检查）

| # | 验收 | 检查方式 |
|---|---|---|
| 1 | `/farewell` → 弹窗；esc 后**什么都没发生**（会话未变、无写入） | 断言 sessionId 与 facts 数不变 |
| 2 | 确认后临终一轮完成，产出放映块 | 渲染断言 |
| 3 | **遗嘱全**：清单条数 == 机械统计（工具调用/事实 id/未闭环工具调用/未完成项） | 逐项比对，差一条即失败 |
| 4 | 散文**至少引用 2 个真实锚点**（文件名/实体/事件），一个都说不出 → 拒 | 与时间线交叉核对 |
| 5 | 放映长度上限（≤ N 行 / ≤ M 字） | 字符计数 |
| 6 | 第二人称「你还记得吗」（或等价引子）存在 | 文本断言 |
| 7 | 禁止流水账词（"综上所述/里程碑/总览/总结"） | 黑名单 |
| 8 | **前缀缓存不受影响**：派发前后主会话装配 SHA-1 逐字节相同 | 复用 `test:divert` 的手法 |
| 9 | 扫光：状态词逐帧变色、**主会话空闲时也在动**（自己的计时器，不挂 busy） | 逐帧渲染断言（同“旁路圆点”那次的测法） |
| 10 | 闪回正文**不得**带扫光色 | 颜色码断言 |
| 10b | **定格后 header 与圆点仍是仪式色**（不得是默认前景/白） | 颜色码断言：行内含 `38;5;97` 且**不含** `\x1b[1m` 单独生效的无色情形 |
| 10c | **逐字吐出**：可见**字符数**随时间单调递增（不是整段出现，也不是按行） | 逐帧渲染，断言字符数严格递增、且中途不存在“半段+换行已完成”的行 |
| 10d | **可跳过且非破坏性**：按键只加速；流式只到几字时按键，后续文字到达**不得丢失** | 回归断言（“只显示三个字”那条） |
| 10i | **不得自动重生**：定稿后出现确认层，由人选择 | 结构护栏 + 弹窗断言 |
| 10e | 节拍：各停顿与 §5.5 常量一致（用注入的假时钟断言，不真等 6 秒） | 注入 `now()` / 假 timer |
| 10f | **ctrl+o 展开**显示完整时间线（未完成项置顶；条目按来源可核对） | 渲染断言 + 条目计数 |
| 10g | 时间线/指路行**列对齐**正确（`visibleWidth`，不得用 `padEnd`） | 逐行可见宽度断言（中文双宽） |
| 10h | 滞后保护**只在超时**才提速：灌入超长文本时总耗时 ≤ `FAREWELL_MAX_MS`；**正常长度下不得提速**（慢是默认） | 灌 200 字 → 断言 ≤ 上限；灌 150 字 → 断言仍按 90ms/字 |
| 11 | `eulogy.md` 落盘；`/resume` 重放放映块 | 文件存在 + 回放断言 |
| 12 | 真实库零写入 | `facts.jsonl` mtime 不变 |
| 11a | **散文长度落在本世档位区间内**（按 §4 公式算档，超出区间即失败） | 字数与档位比对 |
| 11a2 | 长档的**具体条目门槛**达标（原话数 / 托付数 / 未完成项全覆盖） | 与时间线、`facts.jsonl` 交叉计数 |

## 13. 提议：让「下一世」认得出上一世（未实现，待 owner 定）

设计稿总纲写的是「重生后靠结构化记忆**认出上一世**，而不是假装从未死过」。现在的界面里**没有体现**——
新会话起身仍是干净的画像，上一世了无痕迹。这是把「动人」从**那一瞬的散文**扩展到**跨世的连续性**，我判断是最强的一手：

```
（新会话开场，intro 之后）
  ·  这是第 3 世。
  ·  上一世我记得：先跟箭头，再跟共现（memory.ts:REL_TYPES）· 计时器条件要放行旁路（bot-view.ts:975）
```

- **机械可得**：新会话 intro 时，从记忆库取 **1–2 条** `evidence` 指向**上一世会话 id** 的事实（`recall`/`about` 即可），`by=bot`
- **不破缓存**：这是 intro 块（低频、会话内不变），不进 system
- **代价**：需要给会话记录「上一世 id」（`bot.json` 加一个字段 `prev`，一行的浅链）
- 归属：可并入本票，也可另开一张（它动 `session.ts` 的 intro 与 `bot.json`，与本票的放映块相对独立）
