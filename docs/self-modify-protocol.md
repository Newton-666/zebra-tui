# Krystal 自我修改协议（self-modify-protocol）

## 文档地位（先读这节）

本文档是**设计文档 / 人读层**，供 owner 与任何接手的 agent、协作者查阅。
它**不属于 agent 运行时**：不会被装进 system prompt、工具描述或任何代码路径，
对 agent 的行为**零影响**。它存在的意义只有一个——让人点开项目文件夹时，
能看到「agent 修改 Krystal 自身」这件事的规则长什么样。

agent 遵循本协议的保障由三处承载，与本文档解耦：

1. **记忆条目**：Krystal Bot 跨会话记忆中存有本协议要点，自我修改任务开始时主动 recall；
2. **git 纪律**：分支、commit、备份分支全部落盘，owner 任何时刻可查证；
3. **owner 终审**：见门 3，这是唯一的裁决点。

若未来要将其升格为**强制执法**（写入 gate.ts 白名单或 system prompt），
属于独立的升级决策，须 owner 另行拍板。本文档不自动获得执法权。

> 修订 2026-10-17：门 1 原文写「npm test」，实测仓库无此脚本（package.json 只有
> 五个分测 + guard + smoke），已按真实基线修订（owner 批准）。教训：验证链必须
> 逐条实跑过才准写进协议。

## 一、纲领

Krystal 的 harness 可以由 Krystal Bot 自己修改（自举）。
「修车的人坐在车里」的死锁，用四道门拆解。

核心事实：agent 在会话中改的只是工作区文件，**commit 才算数**。
任何坏改动的恢复动作是 owner 敲一条 `git checkout main`——
这一步**不需要 agent 活着**。最坏情形是回滚一个 commit，不是灾难。

本协议已于 2026-09-24 实战预演一次（pi→krystal send 断路修复：
分支施工 + 备份分支推远端 + smoke 全绿后才合入）。

## 二、角色

- **owner**：裁判。唯一拥有合入 main 的权力；只验报告，不验代码细节。
- **agent（Krystal Bot）**：执行者兼自证人。负责门 0-2 并出具报告。
- **本文档**：人读层工件。

## 三、四道门

### 门 0 · 改前（防火墙）

- [ ] 验收标准先行：动手前列出「哪些命令必须过」
- [ ] 在分支上改（`selfmod/<主题>`），main 不碰
- [ ] 一次任务一个 commit——回滚粒度 = 任务粒度
- [ ] 推备份分支到远端（`backup/<日期>-<主题>`）

### 门 1 · 改后（三连验证，专治「重启后跑不起来」）

- [ ] `node --check` 改动的每个文件——语法层，秒级（对 .ts 同样有效）
- [ ] `npm run guard` + `npm run test:memory / test:render / test:commands / test:divert / test:login`
      ——harness 守卫与五套分测全绿（package.json 无 `npm test` 聚合脚本，2026-10-17 实测基线全过）
- [ ] **smoke 启动**：把改后的代码真实启动一次——进程能起、TUI 能画、
      发消息能得到回复。启动验证与真实重启只差「谁在跑」，
      坏结果在 owner 切换之前就会暴露

### 门 2 · 金丝雀（行为验证）

- [ ] 起临时实例（不动常驻实例），跑一遍典型会话：
      发送/回复、记忆五查询、压缩触发、闸门拦截路径
- [ ] 行为确认后，常驻实例才换血（owner 执行重启）

### 门 3 · owner 终审

- [ ] agent 交付验证报告：改了什么 / 为何 / 如何回滚 / 各门命令与输出摘要
- [ ] owner 的规则只有一条：**没有验证报告的发布，一律拒绝**

## 四、回滚预案

```
git checkout main             # 丢弃工作区坏改动
git branch -D selfmod/<主题>   # 可选：删除坏分支
```

owner 敲这两条命令，不需要任何 agent 参与。这就是「变砖」恐惧的解。

## 五、诚实的边界

四道门证明的是「**起得来 + 已知场景不坏**」，不是「未知场景不坏」。
其价值不在保证完美，而在把发现坏改动的时点
从「owner 重启后懵逼」前移到「金丝雀阶段死亡」——
使回滚成为例行动作，而非事故。

## 六、每次任务的执行方式

复制门 0-3 清单作为该任务的 todo，随任务推进逐项打勾；
任务收尾时，验证报告 + 交接说明（改了什么/为何/如何回滚）一并落盘
或写入记忆，保证任何后来者（包括下一个会话的 agent 本人）
不看设计对话也能接管。
