# 决策图 Compaction 方案（Decision Graph）

状态：定稿，待施工。施工方：pi。本文档自足——只读本文即可动工，设计对话原文不需要（需要验证时用文末回链）。
本文档自身即是方案的第一个 dogfood：它就是一份「移交工件」。

## 0. 一句话纲领

Compaction 的产物从「一段摘要文本」换成「一张可移交的决策图」：会话满窗时往图上追加结构化节点，图随会话移交，新会话从图上再水化（rehydrate）衔接。延续的单位是思路（flow），不是状态快照。

## 1. 为什么不用快照式摘要

现状（src/context.ts + src/bot.ts）：compaction 产出六段式/自由摘要文本，本质是**状态量词**（做了什么、下一步是什么）。缺陷有三：

1. **状态不承载因果**。摘要给终点坐标，不给路径；用户为什么否掉 A 选 B、表述如何从模糊走到具体——这些「衔接点」全部蒸发。
2. **文本迭代合并 = 传话游戏**。每次重写摘要，漂移累积，无结构保证。
3. **快照假设计划仍然有效**。真正指向未来的不是 Next Steps 列表，是「用户当前立场在哪」这条活边。

对应缺陷清单（现状代码债，本方案顺带偿还）：真实 usage 已采集未喂触发器；keepRecent 按条数不按 token；有 summary 后不再触发重摘要（context.ts:82），摘要切点与保留窗口之间的消息掉出上下文且不被摘要覆盖（二次压缩鸿沟）；摘要输入每条截 1200 字/总量 12000 字、输出 200 字——容量不足是快照路线被迫有损的根源。

设计立场（owner 原话）：「最有效的方式像 memory 一样用 graph……把整个思路讲清楚，这个思路比状态快照更重要」「agent 必须知道用户前面的 flow，才可能继续契合用户的方式衔接过来——这个衔接点就是 compaction 当中最重要的一环」。

## 2. 神经科学参照（设计直觉来源，施工可跳过）

- 会话事件流 = 海马情节缓冲（完整记录，磁盘不丢）
- 决策图 = 认知地图（Tolman/O'Keefe：海马存关系结构不存散点；新环境不是从头学，是新情节绑定到旧图上）
- 再水化 = 模式补全（部分线索恢复全貌；新会话第一步是等用户开口做补全，不是通读汇报）
- 状态轴 = 痕迹巩固（○ 不稳定痕迹需复述才能存活——写成草案本身就是巩固；◐/● 已巩固；✕ 消退）
- /sleep 远端蒸馏 = 海马→皮层巩固梯度（近端情节鲜活，远端蒸馏成语义）

## 3. 存储态：一行一节点，append-only

文件：`sessions/<session>/decision-graph.jsonl`。一行一个 JSON 节点，只追加，永不改写。参考实现（含 16 节点真实样例）：`graph-demo/decision-graph.jsonl`，渲染器 `graph-demo/render-graph.ts`（92 行纯投影，`--compact` 可切缩略视图）。

```jsonc
{
  "id": "n0042",
  "type": "decision | rejected | refined | discovery | stance",
  "actor": "user | agent",          // user 驱动=偏好，agent 驱动=试探，权重不同
  "state": "floating | committed | landed | rejected",
  "title": "≤20字标题，索引用",
  "body": {
    "what": "做了什么。实质内容，含具体参数/数字/文件",
    "why": "为什么。当时的动机与理由",
    "alternatives": [               // 可选，rejected 节点必带
      { "option": "弃掉的方案", "rejected_because": "拒绝理由，尽量引用户原话" }
    ],
    "consequence": "引向何处。后果与去向"
  },
  "quote": "用户原话≤60字",          // stance 必带，关键 rejected/recommended 带
  "ref": ["msg_id"],                // 回链会话事件流，原文恒可验证
  "edges": [{ "rel": "led-to | rejected-alt | refined-into | superseded", "to": "n0041" }]
}
```

字段铁律：

- **自足性**：只读节点正文就能接着干活，回链原文仅用于验证。正文是决策图的 diff（对应 git 里 commit 指向 blob 而不复述文件）。
- **append-only**：节点状态变化（○→◐→●，或被否决）不修改旧行，追加一行携带同 id 的新状态与 superseded 边。渲染时同 id 取最后一行为准。
- **边必须指向已存在的节点 id**，内核校验，指向不存在节点即拒收——这是链条不断裂的机制保证，防「每次 compaction 各总结各的、图退化成段摘要孤岛」。

## 4. 语义：节点准入、状态轴、边

**节点准入（唯一判据：决策空间的状态变化）**——只有四种变化够格：

1. 承诺形成（定了什么）→ decision
2. 分支被拒（否掉了什么，**带拒绝理由**）→ rejected
3. 表述精化（模糊的想法变具体）→ refined
4. 假设被推翻（发现让前提失效的新事实）→ discovery

寒暄、工具输出、没有产生承诺的探索漫游不进图——留在事件流里做底料。粒度检验：一个长会话产出 **5~15 个节点**；到 50 个说明画成了消息分辨率，退回逐字稿了。

**状态轴（owner 定义：落实与否 = 世界有没有被改变；「单纯的记忆不算」——记忆保存的是承诺的痕迹，不构成承诺本身）**：

| 记号 | state | 含义 | 注意力权重 |
|---|---|---|---|
| ○ | floating | 想法：只在对话里，没落实没承诺 | ▸ 低——待分诊 |
| ◐ | committed | 拍板未落地：承诺存在，工件不存在 | ▸▸▸ 最高——接管者的待办清单 |
| ● | landed | 已落实：工件存在或已执行（含已定稿的设计文档落地） | 零——终态不重开 |
| ✕ | rejected | 已否决：显式终态 | 零——不许复活 |

状态是节点里**唯一朝向未来的字段**：标题、正文、边都是过去时，状态是现在时。接管者按它分配注意力预算。floating 不能无声蒸发：/sleep 审计老化的 ○，三选一——升 ◐、杀 ✕、显式蒸发（记录一条 superseded 事件）。

**边（三种生产动作）**：每次 compaction 模型只做三件事——延长主干（led-to：这个决定导致那个决定）、剪枝存档（rejected-alt：记下被拒分支**和理由**——用户的拒绝是偏好函数的采样点，全图价值密度最高的边）、更新队头（stance 变更走 supersede，不改写——改主意本身就是 flow）。v1 拓扑 = 单主干 + 分支，不做多线程。

## 5. 绘制流程（compaction 时刻发生什么）

分工沿用 /sleep 的既有定案：**模型只出方案，内核只执行事件**。

1. 触发：沿用现有 foldAt/summarizeAt（或升级真实 usage 判定，见 §8）。
2. 模型输入：图尾骨架（最近若干节点的 title+state 一行）+ 本段待压缩对话。
3. 模型输出：结构化节点 JSON 数组（非散文），每个节点带 edges 指向已有节点 id。
4. 内核校验：schema 白名单（type/state/rel 枚举）、必填字段（body.what / ref）、边指向已存在节点。拒收不合格节点，合格者 append。
5. 落盘后旧路径退役：不再生成摘要文本，不再写 note 事件。

失败降级：模型调用失败或校验全拒 → 本轮只折叠工具输出不追加图（同现有「失败只折叠，绝不删」的降级哲学），不阻塞会话。

## 6. 再水化（新会话怎么接）

新会话装配时，决策图块放 system 尾部（同旧摘要的位置，紧跟稳定前缀）：

- **主干骨架**：每节点一行（id + 记号 + title），一行约 40 tokens
- **热头全量**：最近 3 个节点全文（body 四段 + quote）
- **◐ 待办清单**：全部 committed 节点（title + what 一行）
- **○ 分诊队列**：全部 floating 节点

预算参考：100 节点 ≈ 5~6k tokens，可调。远端节点（时间梯度）不 inline，按需查询（related 激活扩散那套）。缓存友好：图块内容只在节点追加时变化，而追加发生在 compaction 时刻——前缀本来就要重算，代价已在预算内，其余回合前缀逐字节稳定。

新会话的第一步是**等用户开口**，用其线索做模式补全——不是通读一份汇报。衔接 = 恢复「未完成」，不是恢复「状态」。

## 7. 人看态：终端渲染

渲染器 = 纯投影，不回写存储。参考实现 `graph-demo/render-graph.ts`。输出结构：

1. 头部：节点统计（●◐○✕ 计数）+ frontier 分组（◐ 待办 / ○ 待分诊）
2. 主干：时间序逐节点，●◐○✕ 记号 + 标题 + 四段正文 + 引语块 + 边注释 + 来源回链
3. 尾部：移交行 + 图例

同一份 JSONL 可出多种投影（TUI 窗格、/sleep 报告），存储态与人看态严格分离。

## 9. 验收：再水化评测

结构检查（机械）：无孤儿节点；每个 decision 必有 ref；◐/○ 必有 body.what；同 id 状态链无环。

再水化评测（语义，真验收尺）：拿图喂一个全新会话，只许读图不许读原文，问只有原会话能答的问题：

- 「这个项目里为什么否掉了 A 方案？」（rejected 边 + 理由是否留存）
- 「现在挂着什么没干？哪些只是想法？」（◐/○ 分辨是否可信）
- 「为什么当时选 X 不选 Y？」（因果链是否完整）
- 「用户在意的到底是什么？」（quote + stance 是否保真）

答得像，图就留住了 flow；答不出，schema 或绘制环节有缺失，回炉。评测题集用 graph-demo 会话（bot-2026-09-24T08-40-39）当第一份材料，标准答案以设计对话原文为准。

## 10. 边界与开放问题

- **范围内**：单项目单任务线的决策图；v1 单主干 + 分支拓扑。
- **范围外**：跨项目图迁移；多线程拓扑；图的自动冲突合并（append-only 使其不需要）。
- 开放问题（不阻塞 P0/P1）：①节点 id 全局计数还是会话前缀（v1 用全局计数 n0001 递增）；②节点质量天花板 = compaction 那次模型调用，抽错靠「改节点不动原文」修复，是否需要节点级 amend 语义待实践定；③TUI 渲染入口放哪（/graph 命令 vs 会话详情页）。
- ref 字段 v1 用消息 id；现 events.jsonl 无消息 id，需先给 msg 事件补 id（P1 内最小改动）。
