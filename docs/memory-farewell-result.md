## 2. 票的要求 → 怎么落的

| 票 | 落地 |
|---|---|
| **时间线由代码机械生成**（全、可核对、零 token） | `buildTimeline`：你说过的话 · 工具调用（带参数摘要）· 本世写入的事实 · **未闭环置顶**；`stats` 一行 |
| **散文由模型写**（温度） | 临终一轮只输出一段连贯散文；指令里给定字数区间与门槛 |
| 长度随本世规模（owner：会话越长越长） | `lifeScale`：`w = 轮数 + 工具数/20` → 四档 60–450 字；**档位越高具体条目门槛越高**（防形容词拉长） |
| 三条硬约束（引原话 / 说未完成 / 留托付） | `validateEulogy` 逐项可测；不合格会被列进 `eulogy.md` 的「校验未过」并在界面 dim 一行提示 |
| 禁模板句 | `EULOGY_BLACKLIST`（“谢谢你的陪伴”这类） |
| 一个字一个字吐出 | 放映块的**吐出队列**，默认 90ms/字；只有**预计超 45s 上限**才提速（慢是默认） |
| 收尾不放路径（owner 反馈“不够触动”） | **折叠 = 情绪**：散文 + `我熄灯了。`；**展开 = 审计**：统计 + 路径（左截断保留尾部）+ 时间线 |
| 定格保留仪式色 | header 与圆点用暮紫 `97`，**不回默认白**（v1 的错误已写进票与测试） |
| 任意键可跳过 | `focusTarget` 里优先处理：有未定格放映块 → `skip()` |
| 自动重生 | 定格 → 写 `eulogy.md` → 停 `FAREWELL.rebirthMs`（2.5s，让人读完）→ 新会话（`life+1`、`prev=旧会话`） |
| §13 下一世认得出上一世 | 新生开场多两行：「这是第 N 世。」「上一世我记得：…」（**只读** recall；不进 system） |
| `/resume` 回放 | 若这一世告别过 → 重放放映块（它在生命最末尾，位置本来就对） |

## 6. 实现中发现/修掉的问题（含我自己踩的）

| # | 问题 | 修法 |
|---|---|---|
| 1 | 时间线条目里工具名重复两次（`run_command  run_command ls`） | `who` 已带名字，`text` 只留参数摘要 |
| 2 | **`advance()` 相位切换丢时间**（一次大跳跃会卡在中间相位） | 改成循环消耗余量；测试改为 50ms 步进（贴近生产时钟） |
| 3 | 路径行被**右截断**吃掉 `eulogy.md` | 长路径**左截断保留尾部** |
| 4 | `recallFromPrevLife` 取**时间窗最早**两条 → 拿不到本世写的（真实场景也会串到别的会话） | 改为**证据优先**（evidence 含会话 id）→ 退化到**近尾优先**（越靠近临终越可能是本世收尾） |
| 5 | 测试自身三处断言写错（轮数应为 2、档位边界、静默起算点） | 逐个改正（测试写错 ≠ 实现错，但要分清） |
| 6 | 结构护栏正则被 `new Date()` 里的 `)` 破坏 | 换成有界 `[\s\S]{0,200}?` |

> 同类教训累积：**“没输出”不等于“不存在”、“字符数”不等于“显示宽度”、参数加了一个就要改所有调用点** —— 这三条今天各踩了一次，都已写进票或代码注释。

## 6b. 端到端第一次跑抓到的 P0（已修，提交 `9bc9d67`）

> **这正是“机器测不了”的那部分** —— 单元测试全绿，但真实一次 `/farewell` 就暴露了两处：

| 现象 | 根因 | 修法 |
|---|---|---|
| **看不到告别段落** | 模型还在写散文时按键 → 旧的 `skip()` 直接冻结 → 冻结成**空的**，界面只剩 header + 引子 + 「我熄灯了。」，2.5 秒后重生 | `skip()` 改成返回 boolean：**散文为空时拒绝跳过**；新增 `waitingForProse`；等待期显示 dim「（正在写……）」（否则按键无反应会被当成坏了） |
| 同上（第二条独立原因） | 放映块**长高时只调 `tui.requestRender()`，没调 `refresh()`** → 滚动区不重算布局，新行可能落不进视口 | 放映时钟改调 `refresh()`（bot-view 里那句注释早写过这个坑：内容变化后必须重算布局） |

顺带加固：`onEvent` 补 `final` 兜底（模型没走流式增量时也能拿到散文）；`settleFarewell` 防空散文
（不写空遗嘱、**不重生**，可再试一次）；重生时才把 `busy` 置回空闲（否则那 2.5 秒里用户输入会落在旧会话上）；
runaway 安全阀（正常溢出不截断，只报“超长”；> 档位上限 3 倍才截）。

新增两条测试：skip 在空散文时必须被拦 + 等待提示可见；经**真实 `Transcript`** 渲染确认告别段落在画面里。

### 6c. 第二次真实跑又抓到两处（提交 `9bc9d67` 之后）

owner 复跑反馈：**“显示了三个字就停下来，然后自动创建了第二世，我都没看完整的。”**

| 现象 | 根因 | 修法 |
|---|---|---|
| **只显示三个字**（`"这一世"`） | 旧 `skip()` 虽已拦住“空散文”，但**散文非空时仍直接 `freeze()`** → `revealed` 被定在**当前已到达的那几个字** → 定格成半句、剩下的永远不显示 | `skip()` 改为**非破坏性**：散文未定稿只记“快进”；调用方在模型回合结束时 `markProseComplete()`，此后快进才全显 + 定格。**未定稿前绝不定格**（typing→silence 的判据加 `complete`） |
| **自动重生、看不完** | `settleFarewell` 里 `setTimeout(rebirth, 2500)` | **改为弹窗确认**：`开始第 N 世 / 留在这里`；重生时才 `busy=false`。另把跳过键从“任意键”收窄到 **enter / space / esc**（其余按键不再劫持，避免误触弄断告别） |

回归测试：**流式只到“这一世”时按键 → 后续文字到达必须不丢**（`revealedChars` == 全文长度）。
票 §5.5/§7/§9 与本节同步更新（重生方式从“自动”改为“弹窗确认”）。

### 6d. 第三次真实跑（owner：“为什么 farewell 以后还能发消息”）

| 现象 | 根因 | 修法 |
|---|---|---|
| 告别写完后**还能往这一世发消息** | 仪式结束时把 `busy` 放开了（为了弹窗），但没有“死后不许说话”的规则 —— 等于刚办完葬礼人又站起来说话 | **死掉的一世拒绝正文消息**：判据直接用 `loadEulogy(sessionId)`（墓志在 = 告别过，**无需新字段**），把“想说话”的意图转成**重生确认弹窗**，且**不清输入框**（开新世后可直接发送）；`/farewell` 第二次也被拒（提示用 `/new`） |

顺带修正：`/new`（无仪式的立刻换一世）也带 `life+1` 与 `prev` —— 否则从死掉的一世用 `/new` 离开，
新一世会显示成“第 1 世”且认不出上一世。
