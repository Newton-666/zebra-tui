## 1. 一条主链（harness 的全部）

```
人类输入 / 平台指令
      │  ① 追加事件（唯一入口）
      ▼
┌─ session.ts ─ events.jsonl（append-only，5 种事件）────────────────────┐
│   msg(user|assistant|tool) · usage · note · intro · meta               │
└────────────────────┬──────────────────────────────────────────────────┘
                     │ loadEvents()
                     ▼
┌─ context.ts ─ 装配（五层预算）────────────────────────────────────────┐
│   system（静态）+ [摘要] + 尾巴        ← **稳定前缀 = 缓存命中区**       │
│   >70% 折叠工具输出 · >85% 远期摘要（压缩=搬迁，原文不删）              │
└────────────────────┬──────────────────────────────────────────────────┘
                     ▼
┌─ bot.ts · streamChat ─ OpenAI 兼容 SSE ───────────────────────────────┐
│   三类 delta：content / reasoning_content / tool_calls                 │
│   空闲看门狗 120s · 重试 3 次 × 10s（仅网络/超时/5xx/429 才重试）      │
└────────────────────┬──────────────────────────────────────────────────┘
                     │ 有 tool_calls？
                     ▼
┌─ bot.ts · executeTool ─ 6 个工具（闸门在前）──────────────────────────┐
│   list_dir · read_file · write_file · edit_file                       │
│   run_command ─► gate.ts  decide()：不可逆 / 隐私 / 围栏+防误删        │
│   memory      ─► memory.ts 事实图 + 五查询 + 九 op + 睡眠协议          │
└────────────────────┬──────────────────────────────────────────────────┘
                     │ 工具结果回填（仍只追加）
                     └────────► 回到装配（循环，**无轮数上限**）
                                        │
                              无 tool_calls → final（落盘）
```

**这就是全部。** 没有第二个循环、没有队列、没有调度器、没有插件系统。

        └──────────────────────────────────────────────────────────┘

**分层教训（有数据）**：近 25 个提交里，核心 13% 改动 / **0 次返工**；视图 23% 改动 / **100% 的真实修复**。
→ **核心必须纯、可离线测；视图只做显示。** UI 可以花哨，但不能与 harness 耦合。

## 3. 两个外部世界（harness 只碰这两个）

| | 文件 | 形状 |
|---|---|---|
| **事件流**（温层） | `sessions/<id>/events.jsonl` | append-only，5 种事件 |
| **记忆**（冷层） | `~/.krystal/facts.jsonl` | append-only，3 种行：`fact` / `fact_update` / `supersede` |
| 人的入口 | `~/.krystal/MEMORY.md` | 幂等重生成 ⇄ 启动时反向导入（人可手改） |
| 上下文窗口 | `~/.krystal/windows.json` | 动态学习（/models 上报 → 超限报错 → 手改） |

其余一切（`eulogy.md`、`diverts/`、`board.md`、`BRIEF.md`）都是**功能层产物**，不是 harness 的一部分。

## 4. 冻结契约（含指纹 —— 可验证）

| 契约 | 值 | 指纹 |
|---|---|---|
| **SYSTEM**（唯一 prompt，静态） | 10 行 / 562 字 | `c58a45237437` |
| **TOOLS**（名字 + 描述） | `list_dir` `read_file` `memory` `run_command` `write_file` `edit_file`（6） | `cdef2b5ef303` |
| **事件类型** | `msg` `usage` `note` `intro` `meta`（5） | — |
| **memory 的 op** | `remember` `recall` `about` `related` `connect` `conflicts` `helpful` `wrong` `supersede`（9） | — |
| **流水线步骤** | 追加 → 装配 → 模型 → 工具 → 回填 → 循环 → final（6 步） | — |
| **重试 / 看门狗 / 阈值** | 3 次×10s · 空闲 120s · 折叠 70% · 摘要 85% | — |
| **闸门判据（类别）** | 不可逆 / 隐私 / 围栏+防误删（3 类；条目可增删但要留档） | — |

> **为什么它们必须冻结**：SYSTEM 与 TOOLS 就是缓存前缀本身。改它们 = 前缀变化 = 历史 KV 全失效
> （§13 判据）。这也是"三件事（/sleep、/divert、/farewell）为什么都没有动 harness"的原因。

## 5. 不允许改（除非命中 §6 的合法理由）

- ❌ **加工具**。工具面永远是 6 个（owner 2026-10-16：只会有"一个终端工具 + 一个记忆"，不再添）
- ❌ **加 prompt 段**。SYSTEM 是静态文案，不放动态状态、不放记忆、不放能力清单
- ❌ **加循环阶段**。一条主链，没有第二循环/队列/调度
- ❌ **把给人看的东西写进 harness**（颜色、文案、布局）——那是视图层的事
- ❌ **为将来抽象**（未被调用的口子、通用机制）——直接删，需要时再加

## 6. 不改 harness 也能加东西：5 个入口

**加功能之前，先在这 5 条里找路；找不到才讨论改 harness。**

| 入口 | 怎么做 | 已有例子 |
|---|---|---|
| ① **追加一条 user 消息（尾巴）** | 平台用自己的话写指令，追加到事件流末尾 → 前缀逐字节不变 | 告别仪式的临终指令 |
| ② **往事件流追加事件** | `msg`/`usage`/`note`，一切历史都靠它 | 工具结果、摘要 note、usage |
| ③ **写文件** | 功能自己的产物放会话目录或 `~/.krystal` | `eulogy.md`、`diverts/`、`board.md` |
| ④ **加命令（UI 层）** | 命令表加一项、`onSubmit` 加一个分支 | `/sleep` `/divert` `/farewell` |
| ⑤ **加视图块（UI 层）** | 自己的文件 + 一行注册（活块契约见 §7） | 旁路块、放映块 |

**改 harness 的合法理由（只有 3 类）**：
1. 上游协议变了（SSE 字段、错误格式、模型窗口上报方式）
2. 安全网发现漏洞（闸门类别内增删条目）
3. 缓存前缀确实必须变（例如换模型协议）——且必须写明代价

## 7. 活块契约（视图层的唯一约定）

新增一种"活块"（会自己动的块）只需满足这个接口 —— **不要**在 `bot-view.ts` 里加 `instanceof` 分支：

```ts
interface LiveBlock extends Component {
  readonly volatile: boolean;   // 未定格 → 逐帧重渲
  expanded: boolean;            // ctrl+o 用
  toggle(): void;
  advance?(ms: number): void;   // 自有节拍（没有就不参与时钟）
}
```

现状：`SubsessionBlock`（旁路）与 `FarewellBlock`（放映）都已满足；`ctrl+o` 与两个计时器**还需泛化成走契约**（见账本待办）。

## 8. 修改前 checklist（给未来的 agent 与我自己）

1. **先看这张图**，确认你要改的是哪一层（harness / 功能层 / 视图层 / 驾驶舱）
2. 若要动 harness：**先回答"能不能用 §6 的 5 个入口达成？"** —— 不能才继续
3. 动了 harness → **更新 §4 指纹** + 在 §9 账本写明理由与代价
4. 跑：`npm run test:memory && npm run smoke`（+ 指纹守卫）
5. 若新增功能：**给出数值理由**（改善哪个可测指标）；**热路径零新增开销**（0 文件 I/O / 0 网络 / 0 新增 prompt 字节）
